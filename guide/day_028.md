# Day 028: Continuous Deployment Pipeline

**Estimated Time:** 2 hours

## Goal
Implement a complete Continuous Deployment (CD) pipeline using GitHub Actions to automatically deploy the Credit Risk Engine to staging and production environments. Include Docker image publishing, environment-specific deployments, smoke tests, blue-green deployment strategy, and automated rollback procedures.

---

## Why Continuous Deployment?

**Problems with Manual Deployment:**
- Human errors during deployment
- Inconsistent deployment process
- Slow release cycles
- No deployment history/audit trail
- Difficult rollbacks
- Deployment anxiety ("works on my machine")

**CD Pipeline Benefits:**
- **Automated**: Same process every time
- **Fast**: Deploy in minutes, not hours
- **Reliable**: Tested, repeatable process
- **Auditable**: Full deployment history
- **Reversible**: Easy rollbacks
- **Confident**: Automated testing reduces risk

**Deployment Flow:**
```
Code Merged → CI Tests Pass →
  Build Docker Image →
  Push to Registry →
  Deploy to Staging →
  Run Smoke Tests →
  Deploy to Production (manual approval) →
  Verify Deployment
```

---

## Key Concepts

### Deployment Strategies

1. **Rolling Deployment**: Update instances one at a time
   - Zero downtime
   - Slow rollback

2. **Blue-Green Deployment**: Two identical environments
   - Instant rollback (switch back)
   - Requires double resources

3. **Can

ary Deployment**: Gradual rollout to subset of users
   - Low risk
   - Complex to implement

### Environments

- **Development**: Developer machines
- **Staging**: Production-like for testing
- **Production**: Live system serving customers

### Deployment Verification

- **Smoke Tests**: Basic health checks after deployment
- **Integration Tests**: Verify service communication
- **Rollback**: Revert to previous version if issues detected

## File 1: CD Workflow - Staging Deployment

**File:** `.github/workflows/cd-staging.yml`

```yaml
# Continuous Deployment to Staging

name: Deploy to Staging

on:
  push:
    branches:
      - develop  # Auto-deploy develop branch to staging

  # Manual trigger
  workflow_dispatch:

env:
  DOCKER_REGISTRY: ghcr.io
  IMAGE_NAME: ${{ github.repository }}/credit-risk-api

jobs:
  # ============================================================================
  # Job 1: Build and Push Docker Image
  # ============================================================================
  build:
    name: Build Docker Image
    runs-on: ubuntu-latest
    permissions:
      contents: read
      packages: write

    outputs:
      image_tag: ${{ steps.meta.outputs.tags }}

    steps:
      - name: Checkout code
        uses: actions/checkout@v4

      - name: Set up Docker Buildx
        uses: docker/setup-buildx-action@v3

      - name: Log in to GitHub Container Registry
        uses: docker/login-action@v3
        with:
          registry: ${{ env.DOCKER_REGISTRY }}
          username: ${{ github.actor }}
          password: ${{ secrets.GITHUB_TOKEN }}

      - name: Extract metadata
        id: meta
        uses: docker/metadata-action@v5
        with:
          images: ${{ env.DOCKER_REGISTRY }}/${{ env.IMAGE_NAME }}
          tags: |
            type=ref,event=branch
            type=sha,prefix={{branch}}-
            type=raw,value=staging-latest

      - name: Build and push Docker image
        uses: docker/build-push-action@v5
        with:
          context: .
          file: ./Dockerfile.prod
          push: true
          tags: ${{ steps.meta.outputs.tags }}
          labels: ${{ steps.meta.outputs.labels }}
          cache-from: type=gha
          cache-to: type=gha,mode=max
          build-args: |
            BUILD_DATE=${{ github.event.head_commit.timestamp }}
            VCS_REF=${{ github.sha }}
            VERSION=staging-${{ github.sha }}

  # ============================================================================
  # Job 2: Deploy to Staging
  # ============================================================================
  deploy-staging:
    name: Deploy to Staging
    runs-on: ubuntu-latest
    needs: build
    environment:
      name: staging
      url: https://staging-api.creditrisk.ng

    steps:
      - name: Checkout code
        uses: actions/checkout@v4

      - name: Deploy to staging server
        uses: appleboy/ssh-action@master
        with:
          host: ${{ secrets.STAGING_HOST }}
          username: ${{ secrets.STAGING_USER }}
          key: ${{ secrets.STAGING_SSH_KEY }}
          script: |
            # Navigate to application directory
            cd /opt/credit_risk_engine

            # Pull latest code
            git pull origin develop

            # Update environment variables
            echo "${{ secrets.STAGING_ENV }}" > .env.staging

            # Pull latest Docker image
            docker pull ${{ needs.build.outputs.image_tag }}

            # Stop current containers
            docker-compose -f docker-compose.staging.yml down

            # Start new containers
            docker-compose -f docker-compose.staging.yml up -d

            # Run database migrations
            docker-compose -f docker-compose.staging.yml exec -T api alembic upgrade head

            # Clean up old images
            docker image prune -af

      - name: Wait for deployment
        run: sleep 30

      - name: Run smoke tests
        run: |
          # Health check
          response=$(curl -s -o /dev/null -w "%{http_code}" https://staging-api.creditrisk.ng/health)
          if [ "$response" != "200" ]; then
            echo "Health check failed: $response"
            exit 1
          fi

          # Metrics endpoint
          response=$(curl -s -o /dev/null -w "%{http_code}" https://staging-api.creditrisk.ng/metrics)
          if [ "$response" != "200" ]; then
            echo "Metrics endpoint failed: $response"
            exit 1
          fi

          echo "✓ Smoke tests passed"

      - name: Notify deployment
        if: success()
        uses: 8398a7/action-slack@v3
        with:
          status: ${{ job.status }}
          text: 'Staging deployment successful! :rocket:'
          webhook_url: ${{ secrets.SLACK_WEBHOOK }}

      - name: Rollback on failure
        if: failure()
        uses: appleboy/ssh-action@master
        with:
          host: ${{ secrets.STAGING_HOST }}
          username: ${{ secrets.STAGING_USER }}
          key: ${{ secrets.STAGING_SSH_KEY }}
          script: |
            cd /opt/credit_risk_engine
            docker-compose -f docker-compose.staging.yml down
            docker-compose -f docker-compose.staging.yml up -d --rollback
```

## File 2: CD Workflow - Production Deployment

**File:** `.github/workflows/cd-production.yml`

```yaml
# Continuous Deployment to Production

name: Deploy to Production

on:
  push:
    tags:
      - 'v*.*.*'  # Trigger on version tags (v1.0.0, v1.2.3, etc.)

  # Manual trigger with approval
  workflow_dispatch:
    inputs:
      version:
        description: 'Version to deploy'
        required: true

env:
  DOCKER_REGISTRY: ghcr.io
  IMAGE_NAME: ${{ github.repository }}/credit-risk-api

jobs:
  # ============================================================================
  # Job 1: Build Production Image
  # ============================================================================
  build:
    name: Build Production Image
    runs-on: ubuntu-latest
    permissions:
      contents: read
      packages: write

    outputs:
      image_tag: ${{ steps.meta.outputs.tags }}
      version: ${{ steps.get_version.outputs.version }}

    steps:
      - name: Checkout code
        uses: actions/checkout@v4

      - name: Get version
        id: get_version
        run: |
          if [ "${{ github.event_name }}" = "push" ]; then
            VERSION=${GITHUB_REF#refs/tags/}
          else
            VERSION=${{ github.event.inputs.version }}
          fi
          echo "version=$VERSION" >> $GITHUB_OUTPUT

      - name: Set up Docker Buildx
        uses: docker/setup-buildx-action@v3

      - name: Log in to GitHub Container Registry
        uses: docker/login-action@v3
        with:
          registry: ${{ env.DOCKER_REGISTRY }}
          username: ${{ github.actor }}
          password: ${{ secrets.GITHUB_TOKEN }}

      - name: Extract metadata
        id: meta
        uses: docker/metadata-action@v5
        with:
          images: ${{ env.DOCKER_REGISTRY }}/${{ env.IMAGE_NAME }}
          tags: |
            type=semver,pattern={{version}}
            type=semver,pattern={{major}}.{{minor}}
            type=raw,value=production-latest
            type=raw,value=${{ steps.get_version.outputs.version }}

      - name: Build and push Docker image
        uses: docker/build-push-action@v5
        with:
          context: .
          file: ./Dockerfile.prod
          push: true
          tags: ${{ steps.meta.outputs.tags }}
          labels: ${{ steps.meta.outputs.labels }}
          cache-from: type=gha
          cache-to: type=gha,mode=max
          build-args: |
            BUILD_DATE=${{ github.event.head_commit.timestamp }}
            VCS_REF=${{ github.sha }}
            VERSION=${{ steps.get_version.outputs.version }}

  # ============================================================================
  # Job 2: Deploy to Production (Blue Environment)
  # ============================================================================
  deploy-blue:
    name: Deploy to Blue Environment
    runs-on: ubuntu-latest
    needs: build
    environment:
      name: production-blue
      url: https://blue-api.creditrisk.ng

    steps:
      - name: Deploy to blue environment
        uses: appleboy/ssh-action@master
        with:
          host: ${{ secrets.PROD_BLUE_HOST }}
          username: ${{ secrets.PROD_USER }}
          key: ${{ secrets.PROD_SSH_KEY }}
          script: |
            cd /opt/credit_risk_engine

            # Update environment
            echo "${{ secrets.PRODUCTION_ENV }}" > .env.production

            # Pull new image
            docker pull ${{ needs.build.outputs.image_tag }}

            # Update docker-compose
            sed -i 's|image:.*|image: ${{ needs.build.outputs.image_tag }}|' docker-compose.prod.yml

            # Deploy
            docker-compose -f docker-compose.prod.yml up -d

            # Run migrations
            docker-compose -f docker-compose.prod.yml exec -T api alembic upgrade head

      - name: Health check blue environment
        run: |
          sleep 30
          response=$(curl -s -o /dev/null -w "%{http_code}" https://blue-api.creditrisk.ng/health)
          if [ "$response" != "200" ]; then
            echo "Blue environment health check failed"
            exit 1
          fi

  # ============================================================================
  # Job 3: Run Production Tests
  # ============================================================================
  production-tests:
    name: Production Verification Tests
    runs-on: ubuntu-latest
    needs: deploy-blue
    environment: production-blue

    steps:
      - name: Checkout code
        uses: actions/checkout@v4

      - name: Run smoke tests
        run: |
          # Test authentication
          response=$(curl -s -X POST https://blue-api.creditrisk.ng/api/v1/auth/login \
            -d "username=healthcheck&password=${{ secrets.HEALTHCHECK_PASSWORD }}" \
            -w "%{http_code}" -o /dev/null)

          if [ "$response" != "200" ]; then
            echo "Authentication test failed"
            exit 1
          fi

          # Test metrics
          curl -s https://blue-api.creditrisk.ng/metrics | grep -q "http_requests_total"

          echo "✓ Production tests passed"

  # ============================================================================
  # Job 4: Switch Traffic (Green → Blue)
  # ============================================================================
  switch-traffic:
    name: Switch Traffic to Blue
    runs-on: ubuntu-latest
    needs: production-tests
    environment:
      name: production
      url: https://api.creditrisk.ng

    steps:
      - name: Update load balancer
        uses: appleboy/ssh-action@master
        with:
          host: ${{ secrets.LOAD_BALANCER_HOST }}
          username: ${{ secrets.LB_USER }}
          key: ${{ secrets.LB_SSH_KEY }}
          script: |
            # Update nginx to point to blue
            sed -i 's|server green-api|server blue-api|' /etc/nginx/sites-available/creditrisk

            # Test configuration
            nginx -t

            # Reload nginx (zero downtime)
            nginx -s reload

      - name: Verify production traffic
        run: |
          sleep 10
          response=$(curl -s -o /dev/null -w "%{http_code}" https://api.creditrisk.ng/health)
          if [ "$response" != "200" ]; then
            echo "Production health check failed"
            exit 1
          fi

      - name: Create GitHub release
        uses: softprops/action-gh-release@v1
        with:
          tag_name: ${{ needs.build.outputs.version }}
          name: Release ${{ needs.build.outputs.version }}
          body: |
            ## Changes in this Release
            - Deployed to production at ${{ github.event.head_commit.timestamp }}
            - Docker image: ${{ needs.build.outputs.image_tag }}

      - name: Notify success
        uses: 8398a7/action-slack@v3
        with:
          status: success
          text: 'Production deployment successful! :rocket: Version: ${{ needs.build.outputs.version }}'
          webhook_url: ${{ secrets.SLACK_WEBHOOK }}

  # ============================================================================
  # Job 5: Update Green Environment (Standby)
  # ============================================================================
  update-green:
    name: Update Green (Standby)
    runs-on: ubuntu-latest
    needs: switch-traffic

    steps:
      - name: Deploy to green environment
        uses: appleboy/ssh-action@master
        with:
          host: ${{ secrets.PROD_GREEN_HOST }}
          username: ${{ secrets.PROD_USER }}
          key: ${{ secrets.PROD_SSH_KEY }}
          script: |
            cd /opt/credit_risk_engine

            # Update to same version as blue
            docker pull ${{ needs.build.outputs.image_tag }}
            docker-compose -f docker-compose.prod.yml up -d

            echo "Green environment updated and ready for rollback"
```

## File 3: Rollback Workflow

**File:** `.github/workflows/rollback.yml`

```yaml
# Emergency Rollback Workflow

name: Emergency Rollback

on:
  workflow_dispatch:
    inputs:
      environment:
        description: 'Environment to rollback'
        required: true
        type: choice
        options:
          - staging
          - production
      version:
        description: 'Version to rollback to (optional)'
        required: false

jobs:
  rollback:
    name: Rollback Deployment
    runs-on: ubuntu-latest

    steps:
      - name: Rollback staging
        if: ${{ github.event.inputs.environment == 'staging' }}
        uses: appleboy/ssh-action@master
        with:
          host: ${{ secrets.STAGING_HOST }}
          username: ${{ secrets.STAGING_USER }}
          key: ${{ secrets.STAGING_SSH_KEY }}
          script: |
            cd /opt/credit_risk_engine

            # If version specified, deploy that version
            if [ -n "${{ github.event.inputs.version }}" ]; then
              docker pull ghcr.io/${{ github.repository }}/credit-risk-api:${{ github.event.inputs.version }}
            fi

            # Rollback using docker-compose
            docker-compose -f docker-compose.staging.yml down
            docker-compose -f docker-compose.staging.yml up -d --rollback

      - name: Rollback production (Blue ← Green)
        if: ${{ github.event.inputs.environment == 'production' }}
        uses: appleboy/ssh-action@master
        with:
          host: ${{ secrets.LOAD_BALANCER_HOST }}
          username: ${{ secrets.LB_USER }}
          key: ${{ secrets.LB_SSH_KEY }}
          script: |
            # Switch traffic back to green
            sed -i 's|server blue-api|server green-api|' /etc/nginx/sites-available/creditrisk
            nginx -t && nginx -s reload

            echo "Traffic switched back to green environment"

      - name: Verify rollback
        run: |
          if [ "${{ github.event.inputs.environment }}" = "staging" ]; then
            URL="https://staging-api.creditrisk.ng/health"
          else
            URL="https://api.creditrisk.ng/health"
          fi

          response=$(curl -s -o /dev/null -w "%{http_code}" $URL)
          if [ "$response" != "200" ]; then
            echo "Rollback verification failed"
            exit 1
          fi

          echo "✓ Rollback successful"

      - name: Notify rollback
        uses: 8398a7/action-slack@v3
        with:
          status: ${{ job.status }}
          text: 'Rollback completed for ${{ github.event.inputs.environment }}'
          webhook_url: ${{ secrets.SLACK_WEBHOOK }}
```

## File 5: Deployment Scripts

**File:** `scripts/deploy-staging.sh`

```bash
#!/bin/bash
#
# Manual staging deployment script
#

set -e

echo "========================================="
echo "  Staging Deployment"
echo "========================================="

# Configuration
STAGING_HOST="${STAGING_HOST:-staging.creditrisk.ng}"
STAGING_USER="${STAGING_USER:-deploy}"
APP_DIR="/opt/credit_risk_engine"

# SSH into staging server and deploy
ssh ${STAGING_USER}@${STAGING_HOST} << 'ENDSSH'
  set -e

  cd /opt/credit_risk_engine

  echo "[1/6] Pulling latest code..."
  git pull origin develop

  echo "[2/6] Pulling Docker images..."
  docker-compose -f docker-compose.staging.yml pull

  echo "[3/6] Stopping services..."
  docker-compose -f docker-compose.staging.yml down

  echo "[4/6] Starting services..."
  docker-compose -f docker-compose.staging.yml up -d

  echo "[5/6] Running migrations..."
  docker-compose -f docker-compose.staging.yml exec -T api alembic upgrade head

  echo "[6/6] Cleaning up..."
  docker image prune -af

  echo "✓ Deployment complete!"
ENDSSH

# Health check
echo "Running health check..."
sleep 10

HEALTH_STATUS=$(curl -s https://staging-api.creditrisk.ng/health | jq -r '.status')

if [ "$HEALTH_STATUS" = "healthy" ]; then
  echo "✓ Staging is healthy!"
else
  echo "✗ Health check failed: $HEALTH_STATUS"
  exit 1
fi
```

**File:** `scripts/deploy-production.sh`

```bash
#!/bin/bash
#
# Manual production deployment script (Blue-Green)
#

set -e

echo "========================================="
echo "  Production Deployment (Blue-Green)"
echo "========================================="

# Detect which environment is currently active
CURRENT=$(ssh deploy@lb.creditrisk.ng "grep 'server.*-api' /etc/nginx/sites-available/creditrisk | awk '{print \$2}' | cut -d'-' -f1")

if [ "$CURRENT" = "green" ]; then
  TARGET="blue"
  TARGET_HOST="blue.creditrisk.ng"
else
  TARGET="green"
  TARGET_HOST="green.creditrisk.ng"
fi

echo "Current: $CURRENT"
echo "Target: $TARGET"

# Deploy to target environment
echo "[1/5] Deploying to $TARGET environment..."
ssh deploy@${TARGET_HOST} << 'ENDSSH'
  cd /opt/credit_risk_engine
  docker-compose -f docker-compose.prod.yml pull
  docker-compose -f docker-compose.prod.yml up -d
  docker-compose -f docker-compose.prod.yml exec -T api alembic upgrade head
ENDSSH

# Health check
echo "[2/5] Running health check on $TARGET..."
sleep 30

HEALTH=$(curl -s https://${TARGET}-api.creditrisk.ng/health | jq -r '.status')
if [ "$HEALTH" != "healthy" ]; then
  echo "✗ Health check failed on $TARGET"
  exit 1
fi

# Switch traffic
echo "[3/5] Switching traffic to $TARGET..."
ssh deploy@lb.creditrisk.ng << ENDSSH
  sudo sed -i 's|server ${CURRENT}-api|server ${TARGET}-api|' /etc/nginx/sites-available/creditrisk
  sudo nginx -t && sudo nginx -s reload
ENDSSH

# Verify
echo "[4/5] Verifying production..."
sleep 10
PROD_HEALTH=$(curl -s https://api.creditrisk.ng/health | jq -r '.status')

if [ "$PROD_HEALTH" = "healthy" ]; then
  echo "✓ Production deployment successful!"
else
  echo "✗ Production health check failed. Rolling back..."

  # Rollback
  ssh deploy@lb.creditrisk.ng << ENDSSH
    sudo sed -i 's|server ${TARGET}-api|server ${CURRENT}-api|' /etc/nginx/sites-available/creditrisk
    sudo nginx -s reload
ENDSSH

  exit 1
fi

echo "[5/5] Updating standby environment..."
# Current becomes new standby
ssh deploy@${CURRENT}.creditrisk.ng << 'ENDSSH'
  cd /opt/credit_risk_engine
  docker-compose -f docker-compose.prod.yml pull
  docker-compose -f docker-compose.prod.yml up -d
ENDSSH

echo "========================================="
echo "  Deployment Complete!"
echo "  Active: $TARGET"
echo "  Standby: $CURRENT"
echo "========================================="
```

Make executable:
```bash

```
