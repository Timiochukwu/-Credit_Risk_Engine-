## Understanding Docker

**What is Docker?**
Docker packages your application and all its dependencies into a container that runs consistently anywhere.

**Key concepts:**

1. **Container:**
   - Lightweight, standalone executable package
   - Includes code, runtime, libraries, settings
   - Isolated from host system

2. **Image:**
   - Blueprint for creating containers
   - Built from Dockerfile
   - Layered filesystem

3. **Dockerfile:**
   - Text file with instructions to build image
   - FROM, COPY, RUN, CMD, etc.

4. **Docker Compose:**
   - Tool for defining multi-container applications
   - YAML configuration file
   - Manages multiple services (API, DB, Redis)

**Why Docker?**
- ✅ **Consistency:** "Works on my machine" → "Works everywhere"
- ✅ **Isolation:** Dependencies don't conflict
- ✅ **Portability:** Deploy to any cloud provider
- ✅ **Scalability:** Easy to scale horizontally
- ✅ **CI/CD:** Automated testing and deployment

**Docker vs Virtual Machines:**
```
VM: Host OS → Hypervisor → Guest OS → App (GBs, slow start)
Docker: Host OS → Docker Engine → Container → App (MBs, instant start)
```

## Step 1: Install Docker

### On Ubuntu/Debian:
```bash
# Update package index
sudo apt update

# Install dependencies
sudo apt install -y apt-transport-https ca-certificates curl software-properties-common

# Add Docker GPG key
curl -fsSL https://download.docker.com/linux/ubuntu/gpg | sudo gpg --dearmor -o /usr/share/keyrings/docker-archive-keyring.gpg

# Add Docker repository
echo "deb [arch=$(dpkg --print-architecture) signed-by=/usr/share/keyrings/docker-archive-keyring.gpg] https://download.docker.com/linux/ubuntu $(lsb_release -cs) stable" | sudo tee /etc/apt/sources.list.d/docker.list > /dev/null

# Install Docker
sudo apt update
sudo apt install -y docker-ce docker-ce-cli containerd.io docker-compose-plugin

# Add user to docker group (avoid sudo)
sudo usermod -aG docker $USER
newgrp docker

# Verify installation
docker --version
docker compose version
```

### On macOS:
```bash
# Install Docker Desktop from https://www.docker.com/products/docker-desktop
# Or use Homebrew
brew install --cask docker
```

### On Windows:
Download and install Docker Desktop from https://www.docker.com/products/docker-desktop

## Step 2: Create Dockerfile

**File:** `Dockerfile`

```dockerfile
# Multi-stage build for smaller final image

# Stage 1: Build stage
FROM python:3.9-slim as builder

# Set working directory
WORKDIR /app

# Install system dependencies
RUN apt-get update && apt-get install -y \
    gcc \
    g++ \
    postgresql-client \
    && rm -rf /var/lib/apt/lists/*

# Copy requirements first (for layer caching)
COPY requirements.txt .

# Install Python dependencies
RUN pip install --no-cache-dir --user -r requirements.txt

# Stage 2: Runtime stage
FROM python:3.9-slim

# Set working directory
WORKDIR /app

# Install runtime dependencies only
RUN apt-get update && apt-get install -y \
    postgresql-client \
    && rm -rf /var/lib/apt/lists/*

# Copy Python packages from builder
COPY --from=builder /root/.local /root/.local

# Copy application code
COPY src/ ./src/
COPY data/ ./data/
COPY .env.example .env

# Create necessary directories
RUN mkdir -p logs mlruns data/models data/monitoring

# Set Python path
ENV PATH=/root/.local/bin:$PATH
ENV PYTHONPATH=/app

# Expose port
EXPOSE 8000

# Health check
HEALTHCHECK --interval=30s --timeout=10s --start-period=40s --retries=3 \
    CMD curl -f http://localhost:8000/health || exit 1

# Run application
CMD ["uvicorn", "src.api.main:app", "--host", "0.0.0.0", "--port", "8000"]
```

**Dockerfile Concepts Explained:**

1. **Multi-stage builds:**
   - `builder` stage: Compiles dependencies
   - `runtime` stage: Only runtime files
   - Result: Smaller final image

2. **Layer caching:**
   - `COPY requirements.txt` before code
   - If requirements unchanged, cached layer reused
   - Faster rebuilds

3. **apt-get cleanup:**
   - `rm -rf /var/lib/apt/lists/*`
   - Removes package lists
   - Reduces image size

4. **HEALTHCHECK:**
   - Docker checks if container is healthy
   - Calls `/health` endpoint every 30s
   - Restarts if unhealthy

5. **Environment variables:**
   - `ENV PATH` - Updates PATH
   - `ENV PYTHONPATH` - Python module search path

## Step 4: Create Docker Compose Configuration

**File:** `docker-compose.yml`

```yaml
version: '3.8'

services:
  # PostgreSQL Database
  postgres:
    image: postgres:15-alpine
    container_name: credit_risk_postgres
    environment:
      POSTGRES_DB: credit_risk_db
      POSTGRES_USER: credit_user
      POSTGRES_PASSWORD: secure_password_123
      PGDATA: /var/lib/postgresql/data/pgdata
    ports:
      - "5432:5432"
    volumes:
      - postgres_data:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U credit_user -d credit_risk_db"]
      interval: 10s
      timeout: 5s
      retries: 5
    networks:
      - credit_risk_network
    restart: unless-stopped

  # Redis Cache
  redis:
    image: redis:7-alpine
    container_name: credit_risk_redis
    ports:
      - "6379:6379"
    volumes:
      - redis_data:/data
    healthcheck:
      test: ["CMD", "redis-cli", "ping"]
      interval: 10s
      timeout: 5s
      retries: 5
    networks:
      - credit_risk_network
    restart: unless-stopped

  # FastAPI Application
  api:
    build:
      context: .
      dockerfile: Dockerfile
    container_name: credit_risk_api
    environment:
      # API Configuration
      API_HOST: 0.0.0.0
      API_PORT: 8000
      DEBUG: "True"
      PROJECT_NAME: "Nigerian Credit Risk Engine"
      VERSION: "0.1.0"

      # Database (using service name as hostname)
      DATABASE_URL: postgresql://credit_user:secure_password_123@postgres:5432/credit_risk_db
      DB_ECHO: "False"

      # Redis
      REDIS_HOST: redis
      REDIS_PORT: 6379

      # Security
      SECRET_KEY: ${SECRET_KEY:-your-secret-key-change-this}
      ALGORITHM: HS256
      ACCESS_TOKEN_EXPIRE_MINUTES: 30
    ports:
      - "8000:8000"
    volumes:
      # Mount code for development (remove in production)
      - ./src:/app/src
      # Persistent data
      - ./data:/app/data
      - ./logs:/app/logs
      - ./mlruns:/app/mlruns
    depends_on:
      postgres:
        condition: service_healthy
      redis:
        condition: service_healthy
    networks:
      - credit_risk_network
    restart: unless-stopped
    healthcheck:
      test: ["CMD", "curl", "-f", "http://localhost:8000/health"]
      interval: 30s
      timeout: 10s
      retries: 3
      start_period: 40s

# Named volumes for data persistence
volumes:
  postgres_data:
    driver: local
  redis_data:
    driver: local

# Custom network
networks:
  credit_risk_network:
    driver: bridge
```

**Docker Compose Concepts:**

1. **Services:**
   - `postgres`: Database server
   - `redis`: Cache server
   - `api`: FastAPI application

2. **Environment variables:**
   - Configure containers without code changes
   - `${VAR:-default}` syntax for defaults

3. **Volumes:**
   - Named volumes: Persistent data (survives container deletion)
   - Bind mounts: Link host directory to container

4. **Networks:**
   - Containers communicate via service names
   - `api` connects to `postgres:5432` (not localhost)

5. **depends_on:**
   - API waits for database to be healthy
   - `condition: service_healthy` checks healthcheck

6. **restart policies:**
   - `unless-stopped`: Always restart except manual stop
   - Good for production

## Step 10: Production-Ready Dockerfile

**File:** `Dockerfile.prod`

```dockerfile
# Production Dockerfile (optimized)

FROM python:3.9-slim

WORKDIR /app

# Install system dependencies
RUN apt-get update && apt-get install -y \
    gcc \
    g++ \
    postgresql-client \
    curl \
    && rm -rf /var/lib/apt/lists/*

# Create non-root user
RUN useradd -m -u 1000 appuser && chown -R appuser:appuser /app

# Copy requirements
COPY requirements.txt .

# Install Python dependencies
RUN pip install --no-cache-dir -r requirements.txt

# Copy application code
COPY --chown=appuser:appuser src/ ./src/
COPY --chown=appuser:appuser data/ ./data/

# Create directories
RUN mkdir -p logs mlruns data/models data/monitoring && \
    chown -R appuser:appuser logs mlruns data

# Switch to non-root user
USER appuser

# Environment
ENV PYTHONPATH=/app
ENV PYTHONUNBUFFERED=1

# Expose port
EXPOSE 8000

# Health check
HEALTHCHECK --interval=30s --timeout=10s --start-period=40s --retries=3 \
    CMD curl -f http://localhost:8000/health || exit 1

# Run with gunicorn for production
CMD ["gunicorn", "src.api.main:app", \
     "--workers", "4", \
     "--worker-class", "uvicorn.workers.UvicornWorker", \
     "--bind", "0.0.0.0:8000", \
     "--access-logfile", "-", \
     "--error-logfile", "-"]
```

**Production improvements:**
1. **Non-root user:** Security best practice
2. **Gunicorn:** Production ASGI server with multiple workers
3. **PYTHONUNBUFFERED:** Immediate log output
4. **Proper file permissions:** `chown` for appuser

To use production Dockerfile:

```bash
docker build -f Dockerfile.prod -t nigerian-credit-risk-api:prod .
```

## Step 11: Docker Compose Override for Development

**File:** `docker-compose.dev.yml`

```yaml
version: '3.8'

services:
  api:
    build:
      context: .
      dockerfile: Dockerfile  # Use dev Dockerfile
    environment:
      DEBUG: "True"
    volumes:
      # Mount source code for hot reload
      - ./src:/app/src
    command: ["uvicorn", "src.api.main:app", "--host", "0.0.0.0", "--port", "8000", "--reload"]
```

**File:** `docker-compose.prod.yml`

```yaml
version: '3.8'

services:
  api:
    build:
      context: .
      dockerfile: Dockerfile.prod
    environment:
      DEBUG: "False"
    # No source code volume in production
    command: ["gunicorn", "src.api.main:app", "--workers", "4", "--worker-class", "uvicorn.workers.UvicornWorker", "--bind", "0.0.0.0:8000"]
```

**Usage:**

```bash
# Development
docker compose -f docker-compose.yml -f docker-compose.dev.yml up

# Production
docker compose -f docker-compose.yml -f docker-compose.prod.yml up
```

```bash
docker system prune -a                    # Remove unused data
```

## Understanding Container Networking

**In Docker Compose:**
```
api container → postgres:5432 (service name as hostname)
NOT → localhost:5432 (localhost refers to container itself)
```

**Network modes:**
- `bridge` (default): Isolated network for containers
- `host`: Use host's network directly
- `none`: No networking

**Service discovery:**
- Containers find each other by service name
- Docker DNS resolves `postgres` → container IP

## Troubleshooting

**Issue:** "Cannot connect to Docker daemon"
**Solution:**
```bash
sudo systemctl start docker
sudo usermod -aG docker $USER
newgrp docker
```

**Issue:** Port already in use
**Solution:**
```bash
# Find process using port 8000
lsof -ti:8000 | xargs kill
# Or change port in docker-compose.yml
```

**Issue:** Container exits immediately
**Solution:**
```bash
# Check logs
docker compose logs api
# Check container status
docker compose ps
```

**Issue:** Cannot connect to database from API
**Solution:**
- Use service name `postgres`, not `localhost`
- Check `DATABASE_URL` environment variable

**Issue:** Changes not reflected (hot reload not working)
**Solution:**
- Ensure volume mount: `./src:/app/src`
- Check `--reload` flag in uvicorn command

**Issue:** Image size too large
**Solution:**
- Use multi-stage builds
- Remove unnecessary files in .dockerignore
- Use Alpine base images
