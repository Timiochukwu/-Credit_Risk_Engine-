# Day 022: Grafana Dashboards & Visualization

**Estimated Time:** 2 hours

## Goal
Install and configure Grafana to create beautiful, interactive dashboards for visualizing Prometheus metrics. Build custom dashboards for monitoring the Credit Risk Engine's performance, predictions, model health, and system resources in real-time.

---

## Why Grafana?

**Prometheus alone gives you:**
- Metric storage
- PromQL queries
- Basic graphing

**Grafana adds:**
- **Professional dashboards**: Beautiful, customizable visualizations
- **Multiple data sources**: Prometheus, PostgreSQL, logs, etc.
- **Alerting**: Visual alerts with notifications
- **Variables**: Dynamic, reusable dashboards
- **Sharing**: Export/import dashboards, share publicly
- **Annotations**: Mark events on graphs (deployments, incidents)

**Real-World Benefits:**
- Executives see business metrics (predictions/day, default rates)
- Engineers debug performance issues (latency spikes, error rates)
- Data scientists monitor model performance (ROC-AUC, drift)
- Operations track infrastructure (CPU, memory, database)

---

## Key Concepts

### Dashboard Components

1. **Panel**: Individual visualization (graph, stat, table, etc.)
2. **Row**: Group of panels (can be collapsed)
3. **Dashboard**: Collection of rows and panels
4. **Variable**: Dynamic value used in queries (like $model_version)
5. **Data Source**: Where data comes from (Prometheus, PostgreSQL)

### Panel Types

- **Time Series**: Line/area graphs for trends over time
- **Stat**: Single value with sparkline and thresholds
- **Gauge**: Visual meter showing current value
- **Bar Chart**: Compare values across categories
- **Table**: Tabular data display
- **Heatmap**: Visualize distribution and density
- **Logs**: Display log entries
- **Alert List**: Show active alerts

### Best Practices

- **Start with Overview**: High-level metrics on first dashboard
- **Drill-Down**: Link detailed dashboards for investigation
- **Consistent Layout**: Use standard grid (24 columns)
- **Meaningful Names**: Clear panel titles
- **Smart Colors**: Green=good, yellow=warning, red=critical
- **Time Ranges**: Show last 24h by default, allow customization

## File 1: Docker Compose with Grafana

**File:** Update `docker-compose.yml`

Add Grafana service:

```yaml
version: '3.8'

services:
  # ... existing services (db, redis, api, prometheus, exporters) ...

  # Grafana
  grafana:
    image: grafana/grafana:latest
    container_name: credit_risk_grafana
    ports:
      - "3000:3000"
    environment:
      - GF_SECURITY_ADMIN_USER=admin
      - GF_SECURITY_ADMIN_PASSWORD=admin123  # Change in production!
      - GF_USERS_ALLOW_SIGN_UP=false
      - GF_SERVER_ROOT_URL=http://localhost:3000
      - GF_INSTALL_PLUGINS=grafana-piechart-panel,grafana-clock-panel
    volumes:
      - grafana_data:/var/lib/grafana
      - ./grafana/provisioning:/etc/grafana/provisioning
      - ./grafana/dashboards:/var/lib/grafana/dashboards
    networks:
      - credit_risk_network
    restart: unless-stopped
    depends_on:
      - prometheus

volumes:
  postgres_data:
  prometheus_data:
  grafana_data:

networks:
  credit_risk_network:
    driver: bridge
```

## File 2: Grafana Data Source Provisioning

**File:** `grafana/provisioning/datasources/prometheus.yml`

```yaml
# Automatically configure Prometheus as data source

apiVersion: 1

datasources:
  - name: Prometheus
    type: prometheus
    access: proxy
    url: http://prometheus:9090
    isDefault: true
    editable: true
    jsonData:
      timeInterval: 15s
      queryTimeout: 60s
      httpMethod: POST
```

**What This Does:**
- Automatically adds Prometheus when Grafana starts
- No manual configuration needed
- Sets Prometheus as default data source

## File 3: Dashboard Provisioning Configuration

**File:** `grafana/provisioning/dashboards/default.yml`

```yaml
# Automatically load dashboards on startup

apiVersion: 1

providers:
  - name: 'Default'
    orgId: 1
    folder: ''
    type: file
    disableDeletion: false
    updateIntervalSeconds: 10
    allowUiUpdates: true
    options:
      path: /var/lib/grafana/dashboards
      foldersFromFilesStructure: true
```

## Creating Custom Dashboards

### Manual Dashboard Creation

1. Click **+** → **Dashboard**
2. Click **Add new panel**
3. In query editor, enter PromQL:
   ```promql
   rate(predictions_total[5m])
   ```
4. Select visualization type (Time series, Stat, etc.)
5. Configure panel options:
   - Title
   - Description
   - Unit
   - Thresholds
6. Click **Apply**
7. Save dashboard

### Adding Variables

Variables make dashboards dynamic and reusable.

1. Click dashboard settings (gear icon)
2. Navigate to **Variables**
3. Click **Add variable**
4. Configure:
   - **Name**: `model_version`
   - **Type**: Query
   - **Data source**: Prometheus
   - **Query**: `label_values(predictions_total, model_version)`
   - **Refresh**: On time range change
5. Save

Now use in queries:
```promql
rate(predictions_total{model_version="$model_version"}[5m])
```

### Linking Dashboards

Create drill-down navigation:

1. Edit panel
2. Go to **Panel links**
3. Add link:
   - **Title**: "View ML Performance"
   - **URL**: `/d/ml-performance?var-model=$model_version`
4. Save

## Production Installation (Without Docker)

### Install Grafana on Ubuntu

```bash
# Add Grafana APT repository
sudo apt-get install -y software-properties-common
sudo add-apt-repository "deb https://packages.grafana.com/oss/deb stable main"

# Add GPG key
wget -q -O - https://packages.grafana.com/gpg.key | sudo apt-key add -

# Update and install
sudo apt-get update
sudo apt-get install grafana

# Start service
sudo systemctl start grafana-server
sudo systemctl enable grafana-server

# Check status
sudo systemctl status grafana-server
```

Grafana will be available at `http://localhost:3000`

### Configure Nginx Reverse Proxy for Grafana

**File:** `/etc/nginx/sites-available/grafana`

```nginx
server {
    listen 80;
    server_name grafana.creditrisk.ng;

    location / {
        proxy_pass http://localhost:3000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

Enable and reload:
```bash
sudo ln -s /etc/nginx/sites-available/grafana /etc/nginx/sites-enabled/
sudo nginx -t
sudo systemctl reload nginx
```

## Common Issues & Solutions

### Issue 1: "Data source is not working"

**Check:**
```bash
# From Grafana container, can it reach Prometheus?
docker exec -it credit_risk_grafana curl http://prometheus:9090/api/v1/targets
```

**Solution:** Ensure both containers on same network

### Issue 2: No data in panels

**Check:**
- Prometheus has data: Visit `http://localhost:9090`
- Time range is appropriate (last 24h)
- Query syntax is correct

**Debug:**
1. Click panel title → **Edit**
2. Click **Query inspector**
3. View actual query and response

### Issue 3: Dashboards not auto-loaded

**Check provisioning:**
```bash
docker exec -it credit_risk_grafana ls /etc/grafana/provisioning/dashboards/
docker exec -it credit_risk_grafana ls /var/lib/grafana/dashboards/
```

**Solution:** Ensure volumes mounted correctly in docker-compose.yml

### Issue 4: Permission denied errors

**Fix permissions:**
```bash
sudo chown -R 472:472 grafana/
```
(472 is Grafana's user ID in Docker)
