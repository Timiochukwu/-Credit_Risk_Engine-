# Day 026: GitHub Actions - CI Pipeline

**Estimated Time:** 2 hours

## Goal
Implement a complete Continuous Integration (CI) pipeline using GitHub Actions to automatically test, lint, scan, and build the Credit Risk Engine on every code change. Ensure code quality, catch bugs early, and maintain consistent standards across the team.

---

## Why CI/CD Pipeline?

**Problems Without CI:**
- Manual testing is error-prone and inconsistent
- Code style varies between developers
- Security vulnerabilities slip through
- Breaking changes discovered in production
- Time wasted on repetitive tasks
- No confidence in code quality

**CI Pipeline Benefits:**
- **Automated Quality Checks**: Every commit is tested
- **Fast Feedback**: Know within minutes if code breaks
- **Consistent Standards**: Enforce code style automatically
- **Security Scanning**: Detect vulnerabilities before deployment
- **Documentation**: Pipeline is living documentation of build process
- **Team Confidence**: Merge with confidence

**Real-World Example:**
```
Developer pushes code → GitHub Actions triggered →
  ✓ Lint code (black, flake8)
  ✓ Type check (mypy)
  ✓ Security scan (bandit)
  ✓ Dependency check (safety)
  ✓ Build Docker image
  ✓ Run tests
  → ✅ All passed → Safe to merge
  → ❌ Any failed → Fix before merge
```

---

## Key Concepts

### GitHub Actions Components

1. **Workflow**: Automated process defined in YAML
2. **Event**: Trigger that starts workflow (push, pull_request, schedule)
3. **Job**: Set of steps that run on same runner
4. **Step**: Individual task (run command, use action)
5. **Runner**: Virtual machine that executes jobs
6. **Action**: Reusable unit of code (checkout, setup-python)

### CI Best Practices

- **Fail Fast**: Run quick checks first (linting before tests)
- **Parallel Jobs**: Run independent tasks simultaneously
- **Cache Dependencies**: Speed up builds with caching
- **Matrix Testing**: Test multiple Python/OS versions
- **Clear Feedback**: Descriptive error messages
- **Secure Secrets**: Never commit credentials

## File 1: Main CI Workflow

**File:** `.github/workflows/ci.yml`

```yaml
# GitHub Actions CI Pipeline for Credit Risk Engine

name: CI Pipeline

on:
  # Trigger on push to any branch
  push:
    branches:
      - '**'

  # Trigger on pull requests to main
  pull_request:
    branches:
      - main
      - develop

  # Allow manual trigger
  workflow_dispatch:

# Cancel in-progress runs when new commit pushed
concurrency:
  group: ${{ github.workflow }}-${{ github.ref }}
  cancel-in-progress: true

env:
  PYTHON_VERSION: '3.9'
  POETRY_VERSION: '1.5.1'

jobs:
  # ============================================================================
  # Job 1: Linting and Code Quality
  # ============================================================================
  lint:
    name: Lint & Code Quality
    runs-on: ubuntu-latest

    steps:
      - name: Checkout code
        uses: actions/checkout@v4

      - name: Set up Python
        uses: actions/setup-python@v4
        with:
          python-version: ${{ env.PYTHON_VERSION }}
          cache: 'pip'

      - name: Install dependencies
        run: |
          python -m pip install --upgrade pip
          pip install black flake8 isort mypy bandit safety

      - name: Run Black (code formatter check)
        run: |
          black --check --diff src/
          echo "✓ Black formatting check passed"

      - name: Run isort (import sorting check)
        run: |
          isort --check-only --diff src/
          echo "✓ Import sorting check passed"

      - name: Run Flake8 (linting)
        run: |
          flake8 src/ --count --select=E9,F63,F7,F82 --show-source --statistics
          flake8 src/ --count --max-complexity=10 --max-line-length=127 --statistics
          echo "✓ Flake8 linting passed"

      - name: Run mypy (type checking)
        continue-on-error: true  # Don't fail build on type errors initially
        run: |
          mypy src/ --ignore-missing-imports
          echo "✓ Type checking completed"

      - name: Run Bandit (security linting)
        run: |
          bandit -r src/ -ll -f json -o bandit-report.json || true
          bandit -r src/ -ll
          echo "✓ Security scanning completed"

      - name: Upload Bandit report
        if: always()
        uses: actions/upload-artifact@v3
        with:
          name: bandit-security-report
          path: bandit-report.json

  # ============================================================================
  # Job 2: Dependency Security Check
  # ============================================================================
  security:
    name: Security Scanning
    runs-on: ubuntu-latest

    steps:
      - name: Checkout code
        uses: actions/checkout@v4

      - name: Set up Python
        uses: actions/setup-python@v4
        with:
          python-version: ${{ env.PYTHON_VERSION }}

      - name: Install dependencies
        run: |
          python -m pip install --upgrade pip
          pip install safety pip-audit

      - name: Check for known vulnerabilities (safety)
        continue-on-error: true
        run: |
          pip install -r requirements.txt
          safety check --json > safety-report.json || true
          safety check

      - name: Audit dependencies (pip-audit)
        continue-on-error: true
        run: |
          pip-audit --desc

      - name: Upload security reports
        if: always()
        uses: actions/upload-artifact@v3
        with:
          name: security-reports
          path: |
            safety-report.json

  # ============================================================================
  # Job 3: Unit Tests (if we had them)
  # ============================================================================
  test:
    name: Run Tests
    runs-on: ubuntu-latest

    # Test matrix - multiple Python versions
    strategy:
      matrix:
        python-version: ['3.9', '3.10', '3.11']

    steps:
      - name: Checkout code
        uses: actions/checkout@v4

      - name: Set up Python ${{ matrix.python-version }}
        uses: actions/setup-python@v4
        with:
          python-version: ${{ matrix.python-version }}
          cache: 'pip'

      - name: Install dependencies
        run: |
          python -m pip install --upgrade pip
          pip install -r requirements.txt
          pip install pytest pytest-cov pytest-asyncio httpx

      - name: Run pytest
        run: |
          # Create tests directory if it doesn't exist
          mkdir -p tests

          # Run tests with coverage (will skip if no tests)
          pytest tests/ -v --cov=src --cov-report=xml --cov-report=term || echo "No tests found"

      - name: Upload coverage to Codecov
        if: matrix.python-version == '3.9'
        uses: codecov/codecov-action@v3
        with:
          file: ./coverage.xml
          flags: unittests
          name: codecov-umbrella
          fail_ci_if_error: false

  # ============================================================================
  # Job 4: Build Docker Image
  # ============================================================================
  build:
    name: Build Docker Image
    runs-on: ubuntu-latest
    needs: [lint, security]  # Only build if lint and security pass

    steps:
      - name: Checkout code
        uses: actions/checkout@v4

      - name: Set up Docker Buildx
        uses: docker/setup-buildx-action@v3

      - name: Build Docker image
        uses: docker/build-push-action@v5
        with:
          context: .
          file: ./Dockerfile
          push: false
          tags: credit-risk-api:${{ github.sha }}
          cache-from: type=gha
          cache-to: type=gha,mode=max

      - name: Test Docker image
        run: |
          docker build -t credit-risk-api:test .
          docker run --rm credit-risk-api:test python --version
          echo "✓ Docker image built successfully"

  # ============================================================================
  # Job 5: Validate Configuration Files
  # ============================================================================
  validate:
    name: Validate Configs
    runs-on: ubuntu-latest

    steps:
      - name: Checkout code
        uses: actions/checkout@v4

      - name: Validate docker-compose.yml
        run: |
          docker-compose config > /dev/null
          echo "✓ docker-compose.yml is valid"

      - name: Validate Prometheus config
        run: |
          docker run --rm -v $(pwd)/prometheus:/prometheus prom/prometheus:latest \
            promtool check config /prometheus/prometheus.yml
          echo "✓ Prometheus config is valid"

      - name: Validate Alert rules
        run: |
          docker run --rm -v $(pwd)/prometheus:/prometheus prom/prometheus:latest \
            promtool check rules /prometheus/alerts.yml
          echo "✓ Alert rules are valid"

      - name: Check for secrets in code
        run: |
          # Install gitleaks
          wget https://github.com/gitleaks/gitleaks/releases/download/v8.18.0/gitleaks_8.18.0_linux_x64.tar.gz
          tar -xzf gitleaks_8.18.0_linux_x64.tar.gz

          # Scan for secrets
          ./gitleaks detect --source . --verbose --no-git || true
          echo "✓ Secret scanning completed"

  # ============================================================================
  # Job 6: Documentation Check
  # ============================================================================
  docs:
    name: Check Documentation
    runs-on: ubuntu-latest

    steps:
      - name: Checkout code
        uses: actions/checkout@v4

      - name: Check for README
        run: |
          test -f README.md || (echo "❌ README.md not found" && exit 1)
          echo "✓ README.md exists"

      - name: Check markdown files
        uses: gaurav-nelson/github-action-markdown-link-check@v1
        with:
          use-quiet-mode: 'yes'
          config-file: '.github/markdown-link-check.json'
        continue-on-error: true

      - name: Check Python docstrings
        run: |
          pip install interrogate
          interrogate src/ -v --fail-under=50 || echo "⚠ Low docstring coverage"

  # ============================================================================
  # Summary Job (always runs)
  # ============================================================================
  ci-summary:
    name: CI Summary
    runs-on: ubuntu-latest
    needs: [lint, security, test, build, validate, docs]
    if: always()

    steps:
      - name: Check job results
        run: |
          echo "## CI Pipeline Results" >> $GITHUB_STEP_SUMMARY
          echo "" >> $GITHUB_STEP_SUMMARY
          echo "- Lint: ${{ needs.lint.result }}" >> $GITHUB_STEP_SUMMARY
          echo "- Security: ${{ needs.security.result }}" >> $GITHUB_STEP_SUMMARY
          echo "- Tests: ${{ needs.test.result }}" >> $GITHUB_STEP_SUMMARY
          echo "- Build: ${{ needs.build.result }}" >> $GITHUB_STEP_SUMMARY
          echo "- Validate: ${{ needs.validate.result }}" >> $GITHUB_STEP_SUMMARY
          echo "- Docs: ${{ needs.docs.result }}" >> $GITHUB_STEP_SUMMARY

          if [[ "${{ needs.lint.result }}" == "failure" ]] || \
             [[ "${{ needs.security.result }}" == "failure" ]] || \
             [[ "${{ needs.test.result }}" == "failure" ]] || \
             [[ "${{ needs.build.result }}" == "failure" ]]; then
            echo "❌ CI Pipeline Failed"
            exit 1
          else
            echo "✅ CI Pipeline Passed"
          fi
```

**Key Features:**
- 6 parallel jobs for fast feedback
- Matrix testing (Python 3.9, 3.10, 3.11)
- Security scanning (bandit, safety, gitleaks)
- Docker image validation
- Configuration validation
- Documentation checks
- Summary report

## Advanced: Caching Strategy

**Update CI workflow with caching:**

```yaml
- name: Cache pip packages
  uses: actions/cache@v3
  with:
    path: ~/.cache/pip
    key: ${{ runner.os }}-pip-${{ hashFiles('**/requirements.txt') }}
    restore-keys: |
      ${{ runner.os }}-pip-

- name: Cache Docker layers
  uses: actions/cache@v3
  with:
    path: /tmp/.buildx-cache
    key: ${{ runner.os }}-buildx-${{ github.sha }}
    restore-keys: |
      ${{ runner.os }}-buildx-
```

**Benefits:**
- 3-5x faster builds
- Reduced network usage
- Lower CI costs

## Common Issues & Solutions

### Issue 1: Black and Flake8 Conflicts

**Problem:** Black formats code that Flake8 complains about

**Solution:** Configure Flake8 to ignore Black-specific issues:
```ini
[flake8]
ignore = E203, E501, W503
```

### Issue 2: CI Runs Too Long

**Problem:** CI takes >10 minutes

**Solutions:**
- Enable caching (pip, Docker layers)
- Run jobs in parallel
- Use faster runners (GitHub hosted)
- Optimize Docker builds

### Issue 3: Secrets in Code Detected

**Problem:** Gitleaks finds false positives

**Solution:** Create `.gitleaksignore`:
```
# False positives
src/utils/config.py:SECRET_KEY
```

### Issue 4: Tests Fail in CI but Pass Locally

**Common Causes:**
- Environment variables not set in CI
- Different Python versions
- Missing dependencies

**Solution:** Match local environment to CI:
```bash
# Use same Python version
pyenv install 3.9.18
pyenv local 3.9.18

# Use same dependencies
pip install -r requirements.txt -r requirements-dev.txt
```
