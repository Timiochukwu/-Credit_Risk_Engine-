## Why Kubernetes?

**Problems with Traditional Deployment:**
- Manual scaling (add/remove servers)
- No self-healing (crashed apps stay down)
- Complex service discovery
- Manual load balancing
- Difficult rolling updates
- Resource underutilization

**Kubernetes Benefits:**
- **Auto-scaling**: Scale based on load
- **Self-healing**: Restart failed containers
- **Service Discovery**: Built-in DNS for services
- **Load Balancing**: Automatic traffic distribution
- **Rolling Updates**: Zero-downtime deployments
- **Resource Optimization**: Pack containers efficiently

**Real-World Example:**
```
Traffic spike → K8s detects high CPU →
  Scales from 3 to 10 pods automatically →
  Distributes load across pods →
  Traffic normalizes →
  Scales back to 3 pods
```

## Key Kubernetes Concepts

### Core Components

1. **Pod**: Smallest deployable unit (1+ containers)
   - Shares network and storage
   - Example: API container

2. **Deployment**: Manages Pod replicas
   - Ensures N pods always running
   - Handles rolling updates
   - Example: 3 replicas of API

3. **Service**: Stable network endpoint
   - Load balances across pods
   - Types: ClusterIP, NodePort, LoadBalancer
   - Example: api-service

4. **ConfigMap**: Configuration data
   - Environment variables
   - Config files
   - Example: APP_ENV=production

5. **Secret**: Sensitive data
   - Passwords, API keys
   - Base64 encoded
   - Example: DATABASE_PASSWORD

6. **Namespace**: Virtual cluster
   - Isolate resources
   - Example: production, staging

### Architecture

```
┌─────────────── Kubernetes Cluster ───────────────┐
│                                                   │
│  ┌─────────────┐  ┌─────────────┐               │

│  │             │  │             │               │
│  │  ┌──────┐   │  │  ┌──────┐   │               │
│  │  │ Pod  │   │  │  │ Pod  │   │               │
│  │  │ API  │   │  │  │ API  │   │               │
│  │  └──────┘   │  │  └──────┘   │               │
│  │             │  │             │               │
│  │  ┌──────┐   │  │  ┌──────┐   │               │
│  │  │ Pod  │   │  │  │ Pod  │   │               │
│  │  │ DB   │   │  │  │Redis │   │               │
│  │  └──────┘   │  │  └──────┘   │               │
│  └─────────────┘  └─────────────┘               │
│                                                   │
│  Service (Load Balancer)                         │
│         ↓                                         │
│    Pods (API)                                     │
└───────────────────────────────────────────────────┘
```

## File 4: PostgreSQL Deployment

**File:** `kubernetes/postgres.yaml`

```yaml
# PostgreSQL StatefulSet

apiVersion: v1
kind: Service
metadata:
  name: postgres-service
  namespace: credit-risk
spec:
  selector:
    app: postgres
  ports:
    - port: 5432
      targetPort: 5432
  clusterIP: None  # Headless service for StatefulSet

---
apiVersion: v1
kind: PersistentVolumeClaim
metadata:
  name: postgres-pvc
  namespace: credit-risk
spec:
  accessModes:
    - ReadWriteOnce
  resources:
    requests:
      storage: 10Gi

---
apiVersion: apps/v1
kind: StatefulSet
metadata:
  name: postgres
  namespace: credit-risk
spec:
  serviceName: postgres-service
  replicas: 1
  selector:
    matchLabels:
      app: postgres
  template:
    metadata:
      labels:
        app: postgres
    spec:
      containers:
      - name: postgres
        image: postgres:14
        ports:
        - containerPort: 5432
          name: postgres
        env:
        - name: POSTGRES_DB
          value: credit_risk_db
        - name: POSTGRES_USER
          value: postgres
        - name: POSTGRES_PASSWORD
          valueFrom:
            secretKeyRef:
              name: postgres-secret
              key: password
        volumeMounts:
        - name: postgres-storage
          mountPath: /var/lib/postgresql/data
        resources:
          requests:
            memory: "512Mi"
            cpu: "500m"
          limits:
            memory: "1Gi"
            cpu: "1000m"
        livenessProbe:
          exec:
            command:
            - pg_isready
            - -U
            - postgres
          initialDelaySeconds: 30
          periodSeconds: 10
        readinessProbe:
          exec:
            command:
            - pg_isready
            - -U
            - postgres
          initialDelaySeconds: 5
          periodSeconds: 5
  volumeClaimTemplates:
  - metadata:
      name: postgres-storage
    spec:
      accessModes: [ "ReadWriteOnce" ]
      resources:
        requests:
          storage: 10Gi

---
apiVersion: v1
kind: Secret
metadata:
  name: postgres-secret
  namespace: credit-risk
type: Opaque
data:
  password: cG9zdGdyZXNfcGFzc3dvcmQ=  # base64: postgres_password
```

## File 6: API Deployment

**File:** `kubernetes/api-deployment.yaml`

```yaml
# Credit Risk API Deployment

apiVersion: apps/v1
kind: Deployment
metadata:
  name: credit-risk-api
  namespace: credit-risk
  labels:
    app: credit-risk-api
    version: v1
spec:
  replicas: 3
  strategy:
    type: RollingUpdate
    rollingUpdate:
      maxSurge: 1
      maxUnavailable: 0
  selector:
    matchLabels:
      app: credit-risk-api
  template:
    metadata:
      labels:
        app: credit-risk-api
        version: v1
      annotations:
        prometheus.io/scrape: "true"
        prometheus.io/port: "8000"
        prometheus.io/path: "/metrics"
    spec:
      containers:
      - name: api
        image: ghcr.io/yourusername/credit-risk-api:latest
        imagePullPolicy: Always
        ports:
        - containerPort: 8000
          name: http
          protocol: TCP
        env:
        # From ConfigMap
        - name: APP_ENV
          valueFrom:
            configMapKeyRef:
              name: credit-risk-config
              key: APP_ENV
        - name: LOG_LEVEL
          valueFrom:
            configMapKeyRef:
              name: credit-risk-config
              key: LOG_LEVEL
        - name: REDIS_URL
          valueFrom:
            configMapKeyRef:
              name: credit-risk-config
              key: REDIS_URL
        # From Secrets
        - name: SECRET_KEY
          valueFrom:
            secretKeyRef:
              name: credit-risk-secrets
              key: SECRET_KEY
        - name: DATABASE_URL
          valueFrom:
            secretKeyRef:
              name: credit-risk-secrets
              key: DATABASE_URL

        resources:
          requests:
            memory: "512Mi"
            cpu: "500m"
          limits:
            memory: "1Gi"
            cpu: "1000m"

        # Health checks
        livenessProbe:
          httpGet:
            path: /health
            port: 8000
          initialDelaySeconds: 30
          periodSeconds: 10
          timeoutSeconds: 5
          failureThreshold: 3

        readinessProbe:
          httpGet:
            path: /health
            port: 8000
          initialDelaySeconds: 10
          periodSeconds: 5
          timeoutSeconds: 3
          failureThreshold: 3

        # Graceful shutdown
        lifecycle:
          preStop:
            exec:
              command: ["/bin/sh", "-c", "sleep 15"]

        # Volume mounts for models
        volumeMounts:
        - name: model-storage
          mountPath: /app/models

      # Init container to run migrations
      initContainers:
      - name: run-migrations
        image: ghcr.io/yourusername/credit-risk-api:latest
        command: ['alembic', 'upgrade', 'head']
        env:
        - name: DATABASE_URL
          valueFrom:
            secretKeyRef:
              name: credit-risk-secrets
              key: DATABASE_URL

      volumes:
      - name: model-storage
        persistentVolumeClaim:
          claimName: model-pvc

---
# Persistent Volume Claim for models
apiVersion: v1
kind: PersistentVolumeClaim
metadata:
  name: model-pvc
  namespace: credit-risk
spec:
  accessModes:
    - ReadWriteMany  # Multiple pods can read
  resources:
    requests:
      storage: 5Gi
```


```bash
kubectl apply -f kubernetes/postgres.yaml
```


## Useful kubectl Commands

### Viewing Resources

```bash
# List all resources in namespace
kubectl get all -n credit-risk

# Describe a pod
kubectl describe pod <pod-name> -n credit-risk

# Get pod logs
kubectl logs <pod-name> -n credit-risk

# Follow logs
kubectl logs -f <pod-name> -n credit-risk

# Logs from previous container (if crashed)
kubectl logs <pod-name> -n credit-risk --previous

# Get events
kubectl get events -n credit-risk --sort-by='.lastTimestamp'
```

### Debugging

```bash
# Execute command in pod
kubectl exec -it <pod-name> -n credit-risk -- /bin/bash

# Port forward to local machine
kubectl port-forward svc/credit-risk-api-service 8000:80 -n credit-risk

# Test from within cluster
kubectl run -it --rm debug --image=curlimages/curl --restart=Never -n credit-risk -- \
  curl http://credit-risk-api-service/health
```

### Managing Resources

```bash
# Scale deployment
kubectl scale deployment credit-risk-api --replicas=5 -n credit-risk

# Restart deployment (rolling restart)
kubectl rollout restart deployment/credit-risk-api -n credit-risk

# Check rollout history
kubectl rollout history deployment/credit-risk-api -n credit-risk

# Rollback to previous version
kubectl rollout undo deployment/credit-risk-api -n credit-risk

# Delete resources
kubectl delete -f kubernetes/api-deployment.yaml
kubectl delete namespace credit-risk  # Deletes everything in namespace
```

## Resource Management

### Understanding Requests and Limits

```yaml
resources:
  requests:     # Minimum guaranteed
    memory: "512Mi"
    cpu: "500m"
  limits:       # Maximum allowed
    memory: "1Gi"
    cpu: "1000m"
```

**CPU:**
- `500m` = 0.5 CPU core
- `1000m` = 1 CPU core

**Memory:**
- `512Mi` = 512 mebibytes
- `1Gi` = 1 gibibyte

**Best Practice:**
- Set requests = typical usage
- Set limits = peak usage
- Monitor and adjust based on metrics

## Common Issues & Solutions

### Issue 1: Pods stuck in Pending

**Check:**
```bash
kubectl describe pod <pod-name> -n credit-risk
```

**Common causes:**
- Insufficient resources
- PVC not bound
- Image pull errors

**Solution:**
```bash
# Check node resources
kubectl top nodes

# Check PVC status
kubectl get pvc -n credit-risk
```

### Issue 2: CrashLoopBackOff

**Check logs:**
```bash
kubectl logs <pod-name> -n credit-risk --previous
```

**Common causes:**
- Application error
- Missing environment variable
- Database connection failure

### Issue 3: ImagePullBackOff

**Check:**
```bash
kubectl describe pod <pod-name> -n credit-risk
```

**Solution:**
- Verify image name and tag
- Check registry credentials
- Use public registry for testing

### Issue 4: Service not accessible

**Check:**
```bash
kubectl get svc -n credit-risk
kubectl get endpoints -n credit-risk
```

**Solution:**
- Verify selector matches pod labels
- Check that pods are ready
- Use port-forward for testing
