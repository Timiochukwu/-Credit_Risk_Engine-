## Goal
Build a comprehensive automated testing strategy for the Credit Risk Engine using pytest, including integration tests for API endpoints, database testing with fixtures, ML model validation tests, test data generation, mocking strategies, and achieving meaningful test coverage.

## Why Automated Testing?

**Problems Without Tests:**
- Manual testing is slow, inconsistent, and error-prone
- Regression bugs slip through unnoticed
- Fear of changing code ("if it works, don't touch it")
- Difficulty onboarding new developers
- No confidence in releases

**Automated Testing Benefits:**
- **Confidence**: Deploy with confidence, knowing tests catch regressions
- **Documentation**: Tests document expected behavior
- **Design**: Writing testable code leads to better architecture
- **Speed**: Automated tests run in seconds vs. hours of manual testing
- **Refactoring**: Change code fearlessly with test safety net

**Testing Pyramid:**
```
        /\
       /  \  E2E Tests (Few)
      /____\
     /      \  Integration Tests (Some)
    /________\
   /          \  Unit Tests (Many)
  /__________  \
```

---

## Key Concepts

### Test Types

1. **Unit Tests**: Test individual functions in isolation
   - Fast, focused, many of them
   - Example: Test feature preprocessing function

2. **Integration Tests**: Test components working together
   - API endpoints, database interactions
   - Example: Test prediction API with real database

3. **End-to-End Tests**: Test complete user workflows
   - Slowest, fewest
   - Example: User registers → logs in → makes prediction

4. **Contract Tests**: Ensure external service contracts honored
   - Example: MLflow API structure hasn't changed

### Testing Principles

- **AAA Pattern**: Arrange → Act → Assert
- **Independent**: Tests don't depend on each other
- **Repeatable**: Same result every time
- **Fast**: Quick feedback loop
- **Isolated**: Use mocks/fixtures for external dependencies

        mocker.patch("src.models.predict.load_model", return_value=mock_model)

## Common Issues & Solutions

### Issue 1: Database fixtures interfere with each other

**Problem:** Tests fail randomly due to database state

**Solution:** Use `scope="function"` for database fixtures (creates fresh DB per test)

### Issue 2: Slow test suite

**Solutions:**
- Use pytest-xdist for parallel execution
- Mark slow tests with `@pytest.mark.slow`
- Skip slow tests in development: `pytest -m "not slow"`

### Issue 3: Mocks not working

**Problem:** Real code executed instead of mock

**Solution:** Ensure correct import path in patch:
```python
# Wrong (won't work if imported differently)
mocker.patch("models.predict.load_model")

# Right (patch where it's used)
mocker.patch("src.api.prediction_routes.load_model")
```
