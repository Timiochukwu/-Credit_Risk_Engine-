# Day 030: Infrastructure as Code with Terraform

**Estimated Time:** 2 hours

## Goal
Learn Infrastructure as Code (IaC) principles using Terraform to provision and manage cloud infrastructure for the Credit Risk Engine. Define servers, databases, networking, and monitoring infrastructure as version-controlled code for repeatable, auditable deployments.

---

## Why Infrastructure as Code?

**Problems with Manual Infrastructure:**
- Undocumented server configurations
- Difficult to replicate environments
- Human errors during setup
- No version control for infrastructure
- Slow disaster recovery
- Configuration drift

**IaC Benefits:**
- Version-controlled infrastructure
- Repeatable deployments
- Self-documenting
- Fast disaster recovery
- Consistent environments
- Infrastructure review process

---

## Terraform Basics

### Key Concepts

1. **Provider**: Cloud platform (AWS, Azure, GCP, DigitalOcean)
2. **Resource**: Infrastructure component (VM, database, network)
3. **State**: Current infrastructure state
4. **Plan**: Preview changes before applying
5. **Apply**: Execute infrastructure changes

### Workflow

```
Write .tf files → terraform init → terraform plan → terraform apply → Infrastructure created
```

## File 1: Terraform Configuration

**File:** `terraform/main.tf`

```hcl
# Main Terraform configuration for Credit Risk Engine

terraform {
  required_version = ">= 1.0"

  required_providers {
    digitalocean = {
      source  = "digitalocean/digitalocean"
      version = "~> 2.0"
    }
  }

  # Remote state storage (uncomment for production)
  # backend "s3" {
  #   bucket = "terraform-state-creditrisk"
  #   key    = "production/terraform.tfstate"
  #   region = "us-east-1"
  # }
}

# Provider configuration
provider "digitalocean" {
  token = var.do_token
}

# Variables
variable "do_token" {
  description = "DigitalOcean API token"
  type        = string
  sensitive   = true
}

variable "environment" {
  description = "Environment name"
  type        = string
  default     = "production"
}

variable "region" {
  description = "Deployment region"
  type        = string
  default     = "nyc3"
}

# SSH Key
resource "digitalocean_ssh_key" "default" {
  name       = "credit-risk-${var.environment}"
  public_key = file("~/.ssh/id_rsa.pub")
}

# VPC Network
resource "digitalocean_vpc" "main" {
  name     = "credit-risk-vpc-${var.environment}"
  region   = var.region
  ip_range = "10.10.0.0/16"
}

# Application Server (Blue)
resource "digitalocean_droplet" "app_blue" {
  name   = "credit-risk-app-blue-${var.environment}"
  size   = "s-2vcpu-4gb"
  image  = "ubuntu-22-04-x64"
  region = var.region
  vpc_uuid = digitalocean_vpc.main.id
  ssh_keys = [digitalocean_ssh_key.default.id]

  tags = [
    "environment:${var.environment}",
    "service:api",
    "slot:blue"
  ]

  user_data = file("${path.module}/scripts/app_setup.sh")
}

# Application Server (Green)
resource "digitalocean_droplet" "app_green" {
  name   = "credit-risk-app-green-${var.environment}"
  size   = "s-2vcpu-4gb"
  image  = "ubuntu-22-04-x64"
  region = var.region
  vpc_uuid = digitalocean_vpc.main.id
  ssh_keys = [digitalocean_ssh_key.default.id]

  tags = [
    "environment:${var.environment}",
    "service:api",
    "slot:green"
  ]

  user_data = file("${path.module}/scripts/app_setup.sh")
}

# Managed PostgreSQL Database
resource "digitalocean_database_cluster" "postgres" {
  name       = "credit-risk-db-${var.environment}"
  engine     = "pg"
  version    = "14"
  size       = "db-s-2vcpu-4gb"
  region     = var.region
  node_count = 1

  tags = [
    "environment:${var.environment}",
    "service:database"
  ]
}

resource "digitalocean_database_db" "credit_risk" {
  cluster_id = digitalocean_database_cluster.postgres.id
  name       = "credit_risk_${var.environment}"
}

resource "digitalocean_database_user" "app_user" {
  cluster_id = digitalocean_database_cluster.postgres.id
  name       = "credit_risk_app"
}

# Load Balancer
resource "digitalocean_loadbalancer" "public" {
  name   = "credit-risk-lb-${var.environment}"
  region = var.region
  vpc_uuid = digitalocean_vpc.main.id

  forwarding_rule {
    entry_port      = 443
    entry_protocol  = "https"
    target_port     = 8000
    target_protocol = "http"
    certificate_name = digitalocean_certificate.cert.name
  }

  forwarding_rule {
    entry_port      = 80
    entry_protocol  = "http"
    target_port     = 8000
    target_protocol = "http"
  }

  healthcheck {
    port     = 8000
    protocol = "http"
    path     = "/health"
  }

  droplet_ids = [digitalocean_droplet.app_blue.id]

  tags = ["environment:${var.environment}"]
}

# SSL Certificate
resource "digitalocean_certificate" "cert" {
  name    = "credit-risk-cert-${var.environment}"
  type    = "lets_encrypt"
  domains = ["api.creditrisk.ng"]
}

# Firewall
resource "digitalocean_firewall" "app" {
  name = "credit-risk-firewall-${var.environment}"

  droplet_ids = [
    digitalocean_droplet.app_blue.id,
    digitalocean_droplet.app_green.id
  ]

  inbound_rule {
    protocol         = "tcp"
    port_range       = "22"
    source_addresses = ["0.0.0.0/0", "::/0"]
  }

  inbound_rule {
    protocol         = "tcp"
    port_range       = "8000"
    source_load_balancer_uids = [digitalocean_loadbalancer.public.id]
  }

  outbound_rule {
    protocol              = "tcp"
    port_range            = "1-65535"
    destination_addresses = ["0.0.0.0/0", "::/0"]
  }
}

# Monitoring Alert
resource "digitalocean_monitor_alert" "cpu_alert" {
  alerts {
    email = ["ops@creditrisk.ng"]
  }

  window      = "5m"
  type        = "v1/insights/droplet/cpu"
  compare     = "GreaterThan"
  value       = 80
  enabled     = true
  entities    = [digitalocean_droplet.app_blue.id, digitalocean_droplet.app_green.id]
  description = "CPU usage above 80%"
}

# Outputs
output "app_blue_ip" {
  value = digitalocean_droplet.app_blue.ipv4_address
}

output "app_green_ip" {
  value = digitalocean_droplet.app_green.ipv4_address
}

output "load_balancer_ip" {
  value = digitalocean_loadbalancer.public.ip
}

output "database_host" {
  value     = digitalocean_database_cluster.postgres.host
  sensitive = true
}

output "database_port" {
  value = digitalocean_database_cluster.postgres.port
}
```

## File 2: Server Setup Script

**File:** `terraform/scripts/app_setup.sh`

```bash
#!/bin/bash
# Cloud-init script for application server setup

set -e

# Update system
apt-get update
apt-get upgrade -y

# Install Docker
curl -fsSL https://get.docker.com -o get-docker.sh
sh get-docker.sh

# Install Docker Compose
curl -L "https://github.com/docker/compose/releases/download/v2.20.0/docker-compose-$(uname -s)-$(uname -m)" \
  -o /usr/local/bin/docker-compose
chmod +x /usr/local/bin/docker-compose

# Create app directory
mkdir -p /opt/credit_risk_engine
chown ubuntu:ubuntu /opt/credit_risk_engine

# Install monitoring agents
curl -sSO https://repos.insights.digitalocean.com/install.sh
bash install.sh

# Setup firewall
ufw allow 22/tcp
ufw allow 8000/tcp
ufw --force enable

echo "✓ Server setup complete"
```

# Reusable app server module

variable "name" {
  description = "Server name"
  type        = string
}

variable "environment" {
  description = "Environment"
  type        = string
}

variable "region" {
  description = "Region"
  type        = string
}

  description = "VPC UUID"
  type        = string
}

variable "ssh_key_id" {
  description = "SSH key ID"
  type        = string
}

resource "digitalocean_droplet" "server" {
  name   = var.name
  size   = "s-2vcpu-4gb"
  image  = "ubuntu-22-04-x64"
  region = var.region
  vpc_uuid = var.vpc_uuid
  ssh_keys = [var.ssh_key_id]

  tags = [
    "environment:${var.environment}",
    "managed-by:terraform"
  ]

  user_data = file("${path.module}/app_setup.sh")
}

output "ipv4_address" {
  value = digitalocean_droplet.server.ipv4_address
}

output "id" {
  value = digitalocean_droplet.server.id
}

## File 6: GitHub Actions Terraform Workflow

**File:** `.github/workflows/terraform.yml`

```yaml
name: Terraform

on:
  pull_request:
    paths:
      - 'terraform/**'
  push:
    branches:
      - main
    paths:
      - 'terraform/**'

jobs:
  terraform:
    name: Terraform
    runs-on: ubuntu-latest

    defaults:
      run:
        working-directory: terraform

    steps:
      - uses: actions/checkout@v4

      - name: Setup Terraform
        uses: hashicorp/setup-terraform@v2
        with:
          terraform_version: 1.5.0

      - name: Terraform Format
        run: terraform fmt -check

      - name: Terraform Init
        run: terraform init
        env:
          DO_TOKEN: ${{ secrets.DO_TOKEN }}

      - name: Terraform Validate
        run: terraform validate

      - name: Terraform Plan
        if: github.event_name == 'pull_request'
        run: terraform plan -no-color
        env:
          DO_TOKEN: ${{ secrets.DO_TOKEN }}
        continue-on-error: true

      - name: Add Plan to PR
        uses: actions/github-script@v6
        if: github.event_name == 'pull_request'
        with:
          script: |
            const output = `#### Terraform Plan 📖
            \`\`\`
            ${{ steps.plan.outputs.stdout }}
            \`\`\`
            `;

            github.rest.issues.createComment({
              issue_number: context.issue.number,
              owner: context.repo.owner,
              repo: context.repo.name,
              body: output
            })

      - name: Terraform Apply
        if: github.ref == 'refs/heads/main' && github.event_name == 'push'
        run: terraform apply -auto-approve
        env:
          DO_TOKEN: ${{ secrets.DO_TOKEN }}
```

## Best Practices

### DO:
- ✅ Use remote state for team collaboration
- ✅ Version lock providers
- ✅ Use modules for reusability
- ✅ Review plans before applying
- ✅ Tag all resources
- ✅ Use variables for flexibility

### DON'T:
- ❌ Commit secrets to git
- ❌ Modify state files manually
- ❌ Apply without planning first
- ❌ Use default resource names
- ❌ Ignore provider version updates
